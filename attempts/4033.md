# POJ 4033 — Lanes

The fresh solve exhausted its five-submission cap with Time Limit Exceeded on every submission. Suggest model parking: the final approach is intended to be linear and agrees with direct simulation, but did not satisfy POJ's 1000 ms total limit. There is no submitted independent reference control and no evidence sufficient to classify a judge fault.

The input gives n1, n2 (1 through 10), m (at most 100000), and r (1 through m), followed by m pairs of arrivals (at most 100 per direction). Arrivals enter before service. Before reversal t the left capacity is n1+1 and right capacity n2. Starting at t the left capacity becomes n1 permanently; starting at t+r the right capacity becomes n2+1 permanently. Sum queues after each service, including all drainage after m. Minimize this total, taking the earliest t on ties. The submitted programs accept datasets until EOF because there is no leading count.

The first implementation evaluated each candidate with prefix queue simulation and suffix queue-cost queries. Given incoming queue q at interval k and post-switch capacity c, let S[i] be cumulative arrivals minus c*i. Before the first i with S[i] <= S[k-1]-q, the queue is S[i]-S[k-1]+q; after that empty interval, a precomputed zero-start suffix cost applies. Prefix sums give the first segment's cost, with a closed-form arithmetic-series drainage tail. A segment tree located the first empty interval. The second implementation replaced it with binary search over a monotone suffix-minimum stack and added buffered fread input. The third used moving fingers and a second stack to remove binary searches. The fourth made prefix sums and queues 32-bit and used 32-bit division for the drainage count; aggregate costs remained 64-bit.

The final implementation instead computes differences between adjacent reversal times. Delaying t to t+1 gives the left an extra unit of capacity at interval t; its benefit is the number of intervals until the affected car would have left the queue under the lower capacity. On the right it removes one unit of capacity at interval t+r; its cost lasts until the first interval with spare capacity under the higher capacity. The distinction is non-strict S[i] <= threshold on the left versus strict S[i] < threshold on the right. Evaluate both lifetimes with suffix minima and a moving threshold finger, then prefix-sum right_cost-left_saving. Earliest strict minimum wins. Each threshold changes by at most a constant per adjacent interval, and stack values are distinct integers, suggesting amortized linear time. Tail lifetimes use integer division. Only the running comparison cost requires 64 bits.

// POJ 4033 - Lanes
// Model: gpt-6.1-sol
// Moving the reversal one interval later saves one car's queue lifetime on
// the left and adds one on the right. Find these lifetimes using suffix minima.
// The threshold finger moves linearly since adjacent lane counts differ by one.
// Strict empty capacity on the right and non-strict emptiness on the left matter.
#include <cstdio>
#include <vector>
#include <algorithm>
using namespace std;
#ifdef _MSC_VER
typedef __int64 LL;
#else
typedef long long LL;
#endif
void costs(const vector<int>& a,int before,int after,int limit,vector<int>& out) {
 int m=(int)a.size()-1; vector<int>s(m+1),q(limit+1),st;st.reserve(m);
 for(int i=1;i<=m;++i)s[i]=s[i-1]+a[i]-after;
 for(int i=1;i<limit;++i)q[i+1]=max(0,q[i]+(i<=m?a[i]:0)-before);
 int ptr=0;
 for(int k=limit;k>=1;--k) {
  if(k>m){out[k]=q[k]/after;continue;}
  while(!st.empty() && s[st.back()]>=s[k])st.pop_back();
  if(ptr>(int)st.size())ptr=(int)st.size();st.push_back(k);
  int h=s[k-1]-q[k]-(before<after);
  while(ptr>0 && s[st[ptr-1]]>h)--ptr;
  while(ptr<(int)st.size() && s[st[ptr]]<=h)++ptr;
  int j=ptr?st[ptr-1]:m+(s[m]-h+after-1)/after;
  out[k]=j-k;
 }
}
int readInt() {

 return v;
}
