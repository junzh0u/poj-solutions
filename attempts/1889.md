# 1889 — Package Pricing

Attempted with gpt-6-astra on 2026-10-15 after the special-judge gate was lifted. The five-submission cap was reached. The remaining issue is Presentation Error; recommend a model park, not a judge park.

## Understanding and algorithm

Read n package descriptions until n=0 or EOF, then m customer lines for each catalogue. Sum repeated bulb letters within each request. Packages can be repeated and may oversupply any bulb size. Sort catalogue numbers before printing the selected package multiplicities. The statement gives no quantity bounds. POJ discussion message 144850 says roughly 20 of each type and fewer than 100 requests, but this is not a guaranteed maximum.

For one customer, define F(a,b,c,d) as the minimum price that covers the residual demand. F(0,0,0,0)=0. Select any nonzero residual coordinate, preferably the one supplied by the fewest catalogue entries, and consider only packages supplying that coordinate. Every feasible multiset includes such a package, so this restriction is complete. Subtract its quantities with saturation at zero and recurse, adding the package price. Memoize mixed-radix state indices and record the selected package to reconstruct a feasible optimal multiset. All edges decrease a positive coordinate, so there are no cycles. Dimensions must be allocated per customer: combining maxima over different customers causes huge unused Cartesian products. For example, four requests individually needing 60 bulbs of only one size each require 61 states apiece, while their combined maxima require 61^4 states.

## Verification and unresolved issue

The 3034-byte version matches the official sample byte for byte. An independent brute-force reference enumerated package count vectors with total count at most the sum of the small requested quantities. This bound is complete for a minimal positive-cost cover: each essential package can be charged to at least one requested bulb. Across 150 deterministic random catalogues with one to five package types, requests of zero through two bulbs per size, and supplies zero through three, all objective values agreed. Each emitted witness was independently checked for sorted unique catalogue numbers, positive multiplicities, coverage of all four demands, and equality of package cost to printed price. A deliberately broken parser that overwrote repeated request letters instead of adding them failed three official sample answers. A 50-package, 99-query test with 20 of all four bulbs per query ran locally in roughly 0.72 seconds for the final per-customer algorithm; actual POJ performance is known only through the verdicts.

Formatting already tested: header exactly `Input set #T:`, customer number immediately followed by colon, price right-aligned in width 8 with two decimal places, a single space before each catalogue number, `(count)` only for multiplicity greater than one, no trailing space and no blank line between datasets; also the two variants described above.
