# 3202 — A Very Simple Compiler

This was previously held by the special-judge gate without any submissions. The gate was explicitly lifted for this run. Four submissions by gpt-6-astra returned Wrong Answer; the five-submission allowance was not exhausted because no further supported hypothesis was found. Suggested park kind: model. There is no evidence sufficient for a judge park.

## Statement and approach

The source is a single expression with at most eight additions or multiplications, parentheses, constants, and x. Each constant and each intermediate result must round to half precision, nearest with ties to even. Exponents 0 and 31, overflow, underflow, and zero are explicitly excluded by the hint. The target instruction reads immediate a and addresses b,c, computes memory[b] -= a with signed 16-bit wraparound, then branches to c if nonnegative or advances by three otherwise. Input and output both occupy word zero. The program must fit in 65,536 words.

The attempted compiler parses a left-associative expression tree with multiplication precedence and evaluates it separately at each of the 61,440 normal half encodings. It stores result bits at address (-input_bits) modulo 65,536. These table addresses occupy 1025..31744 and 33793..64512, leaving low memory available for code. A self-modifying setup uses the input immediate at address zero repeatedly to patch 32 destination operands. It then clears word zero and reads the selected table cell destructively: first its sign, then fifteen magnitude bits by subtracting powers of two, restoring a power after a negative comparison. Each successful test adds that power to output word zero. Programs without x emit six words, like the sample.

The last variant additionally recognizes positive zero and emits the expression evaluated at zero directly. That is defensive handling outside the promised normal input domain. Negative zero and other special encodings remain unsupported.

The official sample reproduces exactly: input `0.499755859375+0.125*(2.0009765625+2)` yields `0 0 3 -15360 0 65535`.

A separate OISC interpreter loaded the emitted program, replaced word zero with each input, and executed wrapped unsigned-short memory with the documented signed branch condition. Four expressions were checked over all 61,440 normal encodings: `x`, `x*1.001+0.1`, `(x+x)*0.25`, and `x*0.5+x*0.25`. Expected half rounding was derived independently using frexp, ldexp, floor, and explicit parity ties, rather than the submitted bit converter. All normal-output comparisons passed. The reference initially differed on negative underflow zero for `(x+x)*0.25`; this is outside the promised domain and was isolated to loss of signed zero in the mathematical reference. Zero-result comparisons were then excluded. The original emitted decoder took at most 148 instructions; the defensive-zero variant took at most 187 in the repeated exhaustive test of `x*1.001+0.1`.

Omitting the intermediate rounding in `x*1.001+0.1` disagreed on 10,521 input encodings, showing that this reference can detect the discussion board's reported pitfall. The constant sample alone does not establish correctness of the runtime decoder. No valid-domain counterexample to the submitted program was found.
