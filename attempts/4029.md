The original specification was recovered from NEERC 2011 problem H, https://neerc.ifmo.ru/archive/2011/neerc-2011.pdf, page 11. It specifies up to 20000 cases, each containing line l1 (four integers), point p1 (two), line l2, and point p2. Coordinates are integers in [-10,10], each point is off its corresponding line, and the two target lines differ. Output any fold line as two points whose x or y coordinates differ by at least 1e-4, with coordinates bounded by 1e9. Both reflected points must be within 1e-4 of their target lines. Four zeroes mean no solution.

The official package is linked as Official tests at https://neerc.ifmo.ru/archive/2011.html: https://neerc.ifmo.ru/archive/2011/neerc-2011-problems.rar (SHA-256 e1785cedb1d4194c8d058a2ead135ab913f9cfe55082352aea0be66555947242). Its huzita directory contains 60 input/answer pairs, Check.java, and jury solutions including huzita_al.java. All 1,096,017 cases were checked locally for solution existence against the jury answers and for the actual reflected-point distances of every nonzero output. Both the corrected original implementation and an independently parameterized translation of the official jury algorithm passed every case. The jury checker explicitly accepts arbitrary valid fold lines, rather than comparing their coordinates textually.

The original algorithm writes each target line as a_i*x+b_i*y+c_i=0 and puts A_i=a_i*p_ix+b_i*p_iy+c_i. In a direction chart n=(1,t), B_i=a_i+b_i*t. Eliminating the fold offset d from d=n dot p_i-A_i*(1+t*t)/(2*B_i) gives the cubic 2*(n dot (p1-p2))*B1*B2-(A1*B2-A2*B1)*(1+t*t)=0. Solve on [-1,1] by derivative critical points and bisection; repeat with swapped axes to cover all directions. Recover d and verify both actual reflections before emitting two points on n dot x=d. For parallel target lines, divide out the common B1 factor before solving: it represents a forbidden direction, since A1 is nonzero. The first implementation failed to cancel this factor, and floating-point rounding near its repeated root could produce a false feasible result.

The official separating case, case 7485 in test 13, is l1=(6,2)-(10,-4), p1=(2,6), l2=(-1,6)-(3,0), p2=(-1,4). Its correct output is four zeroes. The original code wrongly emitted a faraway line near (-139811.6204,209718.4306); exact cancellation fixed it. This was a real solver bug, and the first Wrong Answer cannot by itself implicate the judge. After the fix all official cases passed, as did 19,998 separately constructed feasible cases with direct witness checks.
