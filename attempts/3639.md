# 3639 Exchange Rates

Two submissions, two Wrong Answers; the run was stopped by the user with three attempts unspent. The stopping insight is worth more than the attempts: two independently hardened implementations of the same algorithm drew identical verdicts, which points at a shared misreading of the problem, not at precision or overflow.

## The reading and the algorithm

Canadian/US dollar exchange over a sequence of days, each with a rate; every conversion pays a 3% commission and floors to the cent. The solution modeled a per-day DP over two states — current holdings entirely in CAD cents, or entirely in USD cents — with transitions `floor(c*0.97/rate)` (CAD to USD) and `floor(u*0.97*rate)` (USD to CAD), one combined floor per conversion, answer = the CAD state after the last day.

## What was verified locally

- Both official samples byte-exact, including the worked 1001.60 line.
- Board post by wangjie2008 gives the arithmetic `1000/0.93*0.99*0.97*0.97 == 1001.60`, which matches the algorithm's own optimal path on the sample exactly.
- An alternative "floor twice" reading (floor before commission, floor again after) yields 1001.59 on sample 1 and was ruled out by the sample itself; the single combined floor is what the sample supports.
- Output format `%d.%02d` confirmed by board post 355831.
- 200+ randomized trials against an exact-Fraction Python reference agreed everywhere (up to the point that motivated the `__int128` hardening: the board's "watch type conversion" warning, post 113220, is real — random 365-day rate sequences can overflow 64-bit state).

## Why this is parked as a misreading, not a bug

Submission 2 removes every numeric failure mode submission 1 could have had, and the verdict did not move. The sample and the board's posted arithmetic both agree with the implemented model, so whatever separates it from POJ's data is something the sample cannot see — the same blind spot class as 2125's cost-order ambiguity. The run was stopped before the planned next step: searching external discussion of this exact problem for the model the judge actually uses.
