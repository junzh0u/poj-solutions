## Problem and exact solution

There are 2–100 axis-aligned rectangular windows at strictly increasing positive depths z, with integer coordinates between 1 and 999. The firing point is (b,0,0), with unrestricted b. A shot can be parameterized as x=b+a*z and y=c*z. Boundary contact counts. The input contains one case. The output is UNSOLVABLE or SOLUTION followed by b and one (x,y,z) intersection per window, all coordinates with six decimal places.

The vertical condition is the intersection of [y1[i]/z[i], y2[i]/z[i]]. For each i>j, horizontal feasibility requires (x1[i]-x2[j])/(z[i]-z[j]) <= a <= (x2[i]-x1[j])/(z[i]-z[j]). Intersect these intervals over all pairs. They are sufficient: for a fixed admissible a, every lower intercept bound x1[i]-a*z[i] is no greater than every upper intercept bound x2[j]-a*z[j], so their common intersection is nonempty. Compare fraction bounds by signed integer cross products; magnitudes are below one million. Choose midpoint slopes, then the midpoint of the intersected intercept bounds. This is O(n^2) time and O(n) memory, with exact feasibility decisions and double precision used only for constructing the witness.

## Independent official control and verification

The original NEERC 2004 jury package is https://neerc.ifmo.ru/archive/2004/problems/archive.rar, linked from https://neerc.ifmo.ru/archive/2004.html. It contains `archive/problems/gunman/gunman_gk.dpr`, authored by Georgiy Korneev, and `check.dpr`. The independent control was a faithful C++98 translation of gunman_gk.dpr, changing file input/output to standard streams and formatting every coordinate to six decimals. For the horizontal projection it enumerates all four endpoint pairs of each pair of windows. A candidate through (xa,za),(xb,zb), za<zb, is valid iff x1[k]*(zb-za) <= xa*(zb-za)+(xb-xa)*(z[k]-za) <= x2[k]*(zb-za) for every k. For the vertical projection it enumerates each lower endpoint ray y1[i]/z[i] and checks y1[k]*z[i] <= y1[i]*z[k] <= y2[k]*z[i] for every k. It prints the first feasible candidate in each projection, deriving the firing intercept by xa-(xb-xa)*za/(zb-za). This O(n^3) method has exact integer membership tests and is algorithmically independent of slope-interval elimination.

Both annotated sources compiled with C++98, pedantic warnings, and optimization. Both passed the package's six ready-made inputs (01–06), 500 deterministic random cases of 2–8 windows, and 20 maximum-size feasible cases. The remaining package cases are Pascal generators and were not generated. A Python exact-integer endpoint-enumeration oracle checked classification; emitted six-decimal trajectories were checked for token count, coordinate format, containment, depth, and collinearity. The official checker allows 5e-4 absolute error, fitting x and y slopes by least squares against the printed depths; the local witness checker reproduced this condition. Window containment was tested more tightly at 1e-6. The official sample admits multiple witnesses, so its output was validated geometrically rather than requiring byte equality to its illustrative answer.

The sample does not catch removing the vertical compatibility condition. A separating input does: n=2 with windows `1 1 2 2 1` and `1 5 2 6 2` must be UNSOLVABLE because the vertical slopes [1,2] and [2.5,3] do not overlap. The mutated solution was caught by this case. No discrepancy was found in either real solution.

The POJ discussion warns about precision and printf("%.6lf") versus printf("%.6f"); this run uses fixed six-place iostream output, and the first implementation avoids floating-point feasibility comparisons entirely. No unsupported precision tweak was used after the verdict.
