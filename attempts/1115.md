# 1115 — Statistical Trouble

Four submissions received Wrong Answer. This is a model park: the remaining discrepancy is unresolved, and the public status evidence is too limited to assert that the judge is broken. One of the five permitted submissions remains unused because there is no further concrete hypothesis to test.

The statement asks for cross tables for pairs of questions. Preserve the survey name and each question's complete description lines, map question codes to their input positions, and map each question's answer characters to their input order. Store respondent strings. For every requested pair, count the answer pairs and accumulate the final row and column. Print the descriptions and then a table with six-character right-aligned fields: a header and three lines per answer row and total row. The three lines contain counts, row percentages, and column percentages. A zero denominator yields a dash, including total cells.

The implementation used integer cumulative rounding. For a row of counts x[j] with total T, set S[j] to the prefix sum and emit floor(100*S[j]/T)-floor(100*S[j-1]/T). This is individually a floor or ceiling of 100*x[j]/T and telescopes to 100. Apply the same procedure independently down each column, including the total row and total column distributions. The percentage of a nonempty row or column's own total is 100. Counts are at most 5000 under the statement's 10000-answer bound, so all arithmetic fits int. Arrays were 11 by 11 for at most 10 answers and a total. Parsing used getline, removed a terminal carriage return, and stopped each section at an exact hash character. Question lines start without a space; answer lines start with a space and have their code at index 1. Query question codes occupy indices 0–2 and 4–6, and the title begins at index 8.

The first implementation reproduced the official POJ sample byte for byte. The second added a blank line after the final table: the published contest checker reads until a blank line for every table, although the statement only explicitly requires blank lines between tables. This changed no counts or rounding. Both variants failed. The final blank line should remain in a retry, but it was not demonstrated to explain the rejection.

It formats fields manually, skips empty input lines, and prints a blank line after each table. Thus it differs independently in rounding, formatting, and parsing.
