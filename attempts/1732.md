# 1732 Phone numbers

## The reading and the algorithm

Digit mapping, taken from the figure and confirmed twice against the statement's own worked examples (`WHITEPAWN = 941837296`, `BULLDOG = 2855304`):

```
1 ij   2 abc   3 def   4 gh   5 kl   6 mn   7 prs   8 tuv   9 wxy   0 oqz
```

Trie over each dictionary word's digit encoding, then a shortest-path DP along the number: `dp[i]` is the fewest words covering the first `i` digits, and from each reachable `i` one walk down the trie along `num[i..]` relaxes `dp[j+1]` at every terminal node. Words are reusable — the board confirms it and `73251897325189` → `reality reality` exercises it. Output is the words space-separated, or `No solution.` with the period. Input is read to EOF.

## The official CEOI'99 data is online — start a retry here

<https://www.fi.muni.cz/ceoi1999/phone/> carries `PHONE.C` (the reference solution that generated the answers) together with `PHONE.I1..I10` and `PHONE.O1..O10`. This is the single most valuable artifact found, and it should not be rediscovered.

Submission 2's program **reproduces all ten official expected outputs byte-for-byte**, and also their concatenation as a single ten-data-set file, in 0.05s and 6MB.

`PHONE.C` also settles two statement ambiguities that no amount of local reasoning would recover:

- It hashes words by encoding and **prepends** to the bucket, so a lookup returns the **last** input word with a given encoding. This is why first-wins reproduced only 8 of 10 official cases — it printed `book`, `dike`, `kay` where the official answers are `cool`, `file`, `lay`.
- It encodes `cvt[c & 0x1f]`, which maps `'` to `g` and `-` to `m`. Official cases 4 and 7 genuinely contain an apostrophe and hyphens, confirming the board's 2006 report.

## The contradiction that stopped the run

The control and submission 4 produce identical output formatting, identical line counts on every well-formed input that could be constructed, and identical *word counts* on 700 of 700 randomized cases — differing only in which of several valid minima they choose, on about 12% of cases. Yet the control draws PE and all three of ours draw WA. Every model of the judge fails against that:

- **A fixed answer file** would require the control's choices to match it, but the control breaks ties by Dijkstra heap order, i.e. arbitrarily. Fitting it was attempted — strict versus non-strict relaxation, crossed with first versus last word — and the best agreement with the control on the official cases is 9 of 10. An arbitrary-tie program matching a fixed answer file across a whole data set is implausible.
- **A validating special judge** makes tie-breaks irrelevant, in which case our provably valid and provably minimal answers should also be PE at worst, never WA.
- **A line-count divergence** is ruled out from the other side: the only input shapes where our line count differs from the control's — an integer-overflowing count, a stray trailing number, extra words past the stated count — all make the control *hang*, and the control got PE rather than TLE, so POJ's data contains none of them.

## Where a retry should start

1. **Get POJ's own data shape into view rather than guessing a third time.** The most probable remaining axis is the `'`/`-` words: submission 1 excluded them and may have been non-minimal, submission 2 included them as `g`/`m` and may have printed a word the answer file lacks, submission 4 excluded them again.
2. **Try a trailing space.** `printf("%s ", word)` is the one output shape with direct board evidence of an Accept (messages 171866 and 243892501: `cout << dic[i] << ends` drew WA where `cout << dic[i] << ' '` drew AC), and it is untried. It plausibly explains the control's PE — but note it can only move WA↔PE and never reach AC unless the word content is also right, so it is not a fix on its own.
3. Do **not** re-derive the digit mapping, the trie DP, or the official test data; all three are settled above.
