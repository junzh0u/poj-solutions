The contest problem has an m by n white grid, a black s by s square completely inside it, and only surviving row k. The input is one case: m n s k, then n characters from . and *. Bounds are 1 <= m,n <= 5000, 1 <= s <= min(m,n), and 1 <= k <= m. Output is Unique, Ambiguous, or Impossible according to the number of compatible paintings. Original contest files are black.in/black.out. Samples are (4,4,1,2; ..*.) => Unique, (4,4,2,2; ..**) => Ambiguous, and (4,4,3,2; .*.*) => Impossible.

## Algorithm and control

Let r be the square's top row. Its legal range is 1 through m-s+1; it covers row k exactly when max(1,k-s+1) <= r <= min(k,m-s+1). If the stripe has black cells, they must form a single consecutive run of exactly s cells. That fixes the horizontal placement; the number of compatible top rows determines the answer. If the stripe is entirely white, compatible top rows are those wholly above or below k, and every horizontal placement is possible.

The jury reference computes the latter count directly as (max(0,k-s)+max(0,m-k-s+1))*(n-s+1). For a valid black run, it computes max(0,min(m-s+1,k)-max(1,k-s+1)+1). Zero, one, or more placements produce Impossible, Unique, or Ambiguous. All products are at most 25,000,000, safely inside a signed 32-bit integer. Complexity is O(n) time and a 5001-byte stripe array. This agrees with the earlier derived algorithm but is independently authored canonical code, not another local reimplementation.

To reproduce the submitted control, take black_yp.c, remove exactly the two assert(freopen(...)) lines, normalize source newlines to LF, and prefix these five lines:
