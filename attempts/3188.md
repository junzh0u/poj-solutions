## Statement recap

POJ 3188 "Cellphones" (USACO 2006 February Gold). Cow alphabet is the first
L letters of the English alphabet (1<=L<=26). Assign each letter to one of
B buttons (1<=B<=L) so that each button holds a *contiguous* range of
letters, every letter is used exactly once, to maximize the number of
dictionary words (D<=1000 words, alphabetic, no duplicates, length 1..10,
upper case) whose "predictive text" button-sequence is unique among the
dictionary. Print the max unique count, then the B button letter sets
(alphabetical order per button, buttons listed in increasing order); ties
broken by maximizing letters on button 1, then button 2, etc. Sample
verified locally against an exhaustive brute force (byte-identical to the
official sample, including the hint about CELL/DILL/FILL/FILM colliding).

Time limit 6000ms, memory 65536K, from USACO 2006 February Gold.

## Why this is hard

A partition is fully described by choosing which B-1 of the L-1
letter-adjacent gaps are "cuts". Two same-length words collide iff, for
*every* position where they differ, the two letters at that position lie
in the same button — i.e. no cut lies inside the gap-range
[min(a,b), max(a,b)-1] for that differing position. So a word pair
collides iff the cut set avoids the *union*, over all differing
positions, of these per-position gap-ranges. This union can be several
disjoint sub-ranges (verified by construction: letters 1,2,3,4 with
g(1)=g(2), g(3)=g(4); words (1,4) and (2,3) both collide, with a common
third word between them lexicographically that has a different code —
so "collision classes are contiguous in original lexicographic order" is
false, ruling out a cheap adjacent-pair check).

### Disproved approach 1: naive prefix scalar DP

The obvious dp[i][j] = "max unique words achievable using letters 1..i in
j buttons" with dp[i][j] = max_k dp[k][j-1] + gain(k+1,i) is WRONG: the
score of the best sub-partition of [1,k] into j-1 parts does not
determine which sub-partition is optimal once combined with what comes
after, because a later button's discrimination power can depend on how
an earlier button split letters that are otherwise tied on the
"old-only" objective. I built a proof-by-construction 6-letter, 3-button,
6-word counterexample where two candidate partitions of a length-3
prefix have IDENTICAL "old-only" unique-word scores (tied, so a scalar
DP could pick either), but one of them yields total score 4 and the
other only 2 once combined with the same fixed suffix button. Concretely
(1-indexed letters A..F, alphabet 1..6):
Words: B, C, AC, BC, AF, BF. B=3.
- Partition {A}|{BC}|{DEF}: score 4 (A vs B differ -> distinguished; B vs
  C differ -> B,C both unique; AF vs BF differ at the A/B digit too ->
  both unique).
- Partition {AB}|{C}|{DEF}: B,C become distinguished (+2) but then AF and
  BF collide because A,B now share button 1 (their DEF digit already
  matches), net total only 2.
Both partitions score identically on the length-<=3 prefix alone (their
B,C / AC,BC old-only sub-scores tie by construction), yet the
full-alphabet totals are 4 vs 2. A scalar DP tracking only the best
prefix score cannot tell these apart. I verified computationally (random
stress, 2000+ cases against an exhaustive brute force trying every
C(L-1,B-1) combination for small L,D) that a concrete implementation of
this scalar DP indeed disagrees with brute force on several random small
cases; smallest shrunk failing case: L=8,B=3, words DB,EA,GB,HF,HG,
brute/optimal answer 5 via partition {ABCD}|{EF}|{GH}, naive scalar DP
finds only 3.

### Disproved approach 2: greedy incremental cut placement

Repeatedly adding the single gap-cut that locally maximizes the
resulting unique-word count (until B-1 cuts placed) also fails: on the
5-word L=8,B=3 example above it finds 3 instead of 5; on the 6-word
L=6,B=3 adversarial example above it finds 2 instead of the true 4.

### Approach 3: exact signature-partition DP (provably correct, but exponential in the worst case)

Key structural fact (proved): define, for a DP state at alphabet
position i with j buttons placed, a "signature" for each word = its
sequence of already-decided button ids at revealed positions (letters
<i) plus a wildcard for positions with letters >=i. Two words are "still
viable competitors" iff signatures are identical (for a position where
one word is revealed and the other still pending, they can NEVER collide
again, because any future button id will be strictly greater than any
already-assigned id). This makes "compatibility" an equivalence relation
over the D words that only ever gets refined (never merged) as more cuts
are added, and this refinement is monotone: if partition P refines
partition Q at the same (i,j), P's eventual best score (over any common
future) is always >= Q's. So a DP over (i,j) keeping *all* Pareto-maximal
(non-dominated under refinement) partial word-partitions is exact, with
transitions: from a state at (i,j) choosing next boundary i2 (button j+1
spans letters [i,i2)), refine each old signature class by splitting on
which of its still-pending positions now fall inside [i,i2) vs remain
>=i2.

I implemented this (a brute-force exhaustive C(L-1,B-1) search for small
cases, and the signature-DP with dominance pruning) and it matches brute
force exactly on 5000+ random tests (sizes up to L=9, D=20) AND on every
constructed adversarial case above, including the ones that broke
approaches 1 and 2. However the number of distinct Pareto-maximal
signature-partitions explodes far too fast to be usable at the problem's
real scale: with a uniform-random alphabet and L=26, B=13, state count
(summed over the whole DP table) was: D=100 -> ~1.4k states (0.3s),
D=120 -> ~6k states (4s), D=150 -> ~16k states already >20s to complete
exhaustively, and D=200 did not finish in 100s. The same blowup happens
with a sample of 1000 real English dictionary words filtered to
length<=10 (did not finish in 30s even restricted to a ~150-word subset,
let alone D=1000). This looks like genuine combinatorial explosion in
the state space (not just an implementation constant-factor issue — I
optimized from string-keyed hashing down to fixed positional
integer-vector keys and the growth rate barely changed), so this exact
algorithm is not viable for D up to 1000 as the problem allows, despite
being provably correct for any size that finishes in time.

I did NOT find a polynomial (or otherwise scalable) exact algorithm for
this problem within my search+reasoning budget. I was also unable to
find a published editorial/analysis or a reference implementation online
(web search for the USACO 2006 February Gold "Cell Phone" analysis,
Chinese-language POJ 3188 writeups, and GitHub/grep.app/Sourcegraph code
search for characteristic phrases all came up empty or were blocked by
auth walls). The old USACO training-page mirrors that sometimes carry
2006-era analyses were not locatable via search either.

2. Reconsider whether the intended solution bounds the *effective*
   branching by something structural in real dictionaries (e.g. trie
   branching factor) that synthetic/random dictionary tests don't
   reflect, and whether a beam-limited version of the exact
   signature-partition DP (keeping only the top-K partitions by an
   admissible upper bound, e.g. D minus the count of already-doomed
   same-signature classes with zero pending positions) could still be
   exact in practice while bounding worst-case work — this was not
   tried.
3. Note the ALSO-unsolved secondary requirement: this attempt only
   verified the *max unique count*; reconstructing the actual button
   assignment (and applying the tie-break rule: maximize letters on
   button 1, then button 2, ...) from the signature-DP requires
   additional bookkeeping (the DP as built forgets concrete cut
   positions/unused-letter placement once it canonicalizes to word
   partitions) that was not yet implemented.
4. Zero submissions were made to POJ for this run — all effort went into
   local algorithm design/verification, so the 5-submission budget is
