# POJ 3582 — Last Hit

No submission was made. The unresolved issue is an efficient exact solution of the simultaneous game, rather than a demonstrated judge defect.

The statement gives M, d, Attack1, Time1, Attack2, Time2, all below 10000, with d positive, and multiple cases through EOF. Health decreases continuously at rate d. A hero can fire only when his previous bullet has arrived. The goal is to force the last hit; simultaneous arriving bullets that together kill award Player1. A bullet arriving exactly when disease would kill still counts. The sample is duplicated deliberately to illustrate multiple cases.

Timing is underspecified in the statement: it does not explicitly restrict firing to integer seconds. Discussion message 108149 says “this is a integer problem,” replying to message 99268's observation that a real-valued random delay changes the game. The integer interpretation was used for the exploratory exact solver; this is a discussion claim, not an official clarification. Message 97763 explains the simultaneous-choice uncertainty with input `100 25 25 2 50 2`. Both fire immediately: Player1 wins. Neither fires immediately: after one second Player1 can fire a lethal shot for arrival at time 3. If only one fires initially, Player2 can win. Thus Player1 wants to match Player2's initial action while Player2 wants to mismatch it, and neither has a sure winning pure strategy.

An exact finite-horizon game can use state (h, x, y), where h is current positive health after processing all arrivals at the current integer time, and x/y are the remaining flight times of the respective pending bullets, or zero if ready. Each ready hero simultaneously chooses fire or wait; a busy hero has only wait. Advance a second, subtract d, process all arriving damage together, check the priority rule, and recurse. If disease reaches zero strictly before an arrival, the outcome is God. A player has a guaranteed win if one of that player's actions makes every opponent action lead to that player's guaranteed win. If every action pair leads to God, return God; otherwise return uncertain. In particular, treating uncertainty as a deterministic player win would invalidate the recurrence.

The exploratory solver jumps directly to the next arrival when both heroes are busy, since neither can act during that interval. Its outputs agree with an independent memoized solver that always advances exactly one second on every positive integer parameter combination with M=1..8, d=1..2, attacks=1..3, and travel times=1..3: 1296 cases. Both return uncertain for `100 25 25 2 50 2`, so the reference can detect the class missing from the sample. Both reproduce Player2 for `100 1 1000 100 10 10`. The sample also agrees with simply firing continuously, so it does not distinguish the actual game from that incorrect simplification.

Discussion message 137331 offers three further checks, all reproduced by the game recurrence: `100 1 100 10 40 1` gives Player2; `100 1 1 1 100 10` gives Player1; `100 100 50 2 50 2` gives God. These are reasoning examples from a participant, not accepted judge data.

The recurrence's state count remains too large. With a conservative 300000 memo-state ceiling, it exceeds the ceiling on `1000 1 1 250 1 250` and on `9999 1 1 2500 1 2500`. This already fails to establish compliance with the 2000MS / 65536K limits, and a C++ translation alone does not resolve the worst-case number of states. No source was submitted because the scalability argument is missing.

A possible structural reduction: with positive Attack1 and strictly smaller Time1 than Time2, Player1 can observe Player2's firing and then fire later to arrange simultaneous arrivals, retaining the tie priority; if Player2 never fires, Player1 can aim at natural death. This seems to settle that region, provided a Player1 bullet can arrive before natural death. It does not yet solve the equal-time or slower-Player1 region. Zero attacks and zero travel times are not explicitly excluded by the statement and need careful treatment as well; the tests above used positive attacks and times.
