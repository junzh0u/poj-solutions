# POJ 1892 - VTAS - Vessel Traffic Advisory Service

The first implementation received Wrong Answer. The main obstacle is the exact warning output contract, especially grouped names and the ordering and timing of warnings. No independently accepted reference or published judge data was recovered. A stronger solver should settle these rules before further submissions.

The raw POJ statement defines directed, positive-distance lanes; zero means no lane. Vessel entry times are in chronological order modulo midnight, with no more than 24 hours between entries. Travel takes distance * 60 / speed minutes. Invalid routes contain an unknown waypoint or a zero-distance transition. Invalid vessels receive only the header and invalid-route message. The sample reports conflicts against later-entering vessels too, so all vessel records must be read before rendering any report.

The attempted algorithm mapped waypoint characters to matrix indices, unwrapped entries by adding one day whenever the clock time decreased, and accumulated unrounded double arrival times. Each arrival was independently rounded with floor(time + 0.5), reduced modulo 1440, and printed in HHMM form. For each valid vessel, each route waypoint generated its close-passing warning before the outgoing leg's encounter warning. A close passing meant equal waypoint characters and arrival difference at most three minutes, including endpoints. An encounter meant the same unordered endpoint pair and a strictly positive overlap of the two open transit intervals. This follows the statement's definition of simultaneous presence between common waypoints, rather than requiring the vessels physically to cross.

All other valid vessels qualifying for an event were collected on one line, with duplicate vessel names suppressed even if that vessel revisited the location. For encounter grouping, names were sorted by the other vessel's departure time on the matching leg, then its initial entry time. For close passing, they were sorted by the other vessel's arrival time at that waypoint, then its initial entry time. Multiple qualifying occurrences of one other vessel used its earliest qualifying event time. Names were separated by a single space. These last grouping and close-passing sorting rules are hypotheses, not verified requirements.

The literal output templates used were:

```
NAME entering system at HHMM with a planed speed of S.S knots
-- Waypoints:    A    B
-- Arrival:   HHMM HHMM
++ Close passing with NAME at Waypoint A
++ Project encounterg with NAME on leg between Waypoints A and B
!! Invalid Route Plan for Vessel: NAME
```

The misspellings `planed` and `encounterg` are present in POJ's sample. Every waypoint occupies five columns after `-- Waypoints:`. Arrival output begins with `-- Arrival:  ` and then one space plus four digits per waypoint. One blank line was emitted after each vessel, including the last.
