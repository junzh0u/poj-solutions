## Claude-in-Chrome transport for the submit step

How the harness-neutral submit contract in `AGENTS.md` §3 maps onto claude-in-chrome. Only these lines should need touching when the extension or its tools change.

- Before building the payload, validate provenance: the source must carry exactly one `// Model: <the id assigned to this agent>` line. `.agents/skills/backlog-loop/scripts/build-submit-js` is the reference check — it refuses to build a payload otherwise. A wrong `// Model:` line found after Accepted costs either another submission or a falsified archive.
- Serialize the click with the shared coordinator `AGENTS.md` §"Solving several at once" calls for: with the tab open and the payload built, run `.agents/skills/backlog-loop/scripts/with-submit-lock true` (repo-root-relative — solve agents build in the scratchpad) in the foreground — it blocks until 15s after the last recorded attempt, then stamps this one — and make the guarded `javascript_tool` click the **very next** tool call, with nothing in between. Same for every retry. This is where the Claude path deviates from Codex's, which keeps the click inside the lock by running it as the helper's child: an MCP call cannot be a subprocess, and a solve subagent cannot pause to ask the parent for a grant. The reservation stamp is the whole mutual exclusion here, so if anything intervenes after it — an error, a stale tab, a sibling re-navigate — reserve again rather than clicking late. `POJ_SUBMIT_COORDINATOR_DIR` and `POJ_SUBMIT_MIN_INTERVAL` are for testing the helper, not for runs.
- Open the tab with `tabs_create_mcp`, run the whole guarded plant-and-click as **one** `javascript_tool` call, and close it with `tabs_close_mcp` on the next tool call. This transport needs **no** landing window: by the time `javascript_tool` returns, Chrome has already committed the POST. Measured 2026-08-06 by resubmitting an archived 2455 source and closing the tab as the immediately following call — run 25194696, Accepted, 3401B. The five-second wait Codex's note requires is an AppleScript-path rule (`AGENTS.md` §3); do not import it here.
- A `javascript_tool` error or unexpected return *after* the click proves nothing in either direction. Read authoritative `curl` status before retrying or closing anything.
- If the tools report several connected Chromes and demand a choice, do not stop to ask — a subagent cannot reach the user; `select_browser` with any deviceId. Only one Chrome may hold the POJ login: if the submit form is missing, try the other browser before concluding the session is gone.
- A stored tabId can go stale outright, not just get re-navigated: sibling churn can close the tab or reassign the whole tab group (`tabs_context_mcp` returns a different `tabGroupId`). On any targeting error, re-run `tabs_context_mcp` and redo navigate + submit as one unit — after checking the status page in case the click already fired.
- The extension blocks `document.cookie` reads — this is why curl cannot borrow the session and the post happens in-page at all.
- Plain `atob` is the whole payload path. The gzip variant (`DecompressionStream`) shrinks long sources to a third but has thrown `Failed to fetch` in this page context; reach for it only when the plain payload is genuinely unwieldy.
- `get_page_text` truncates at 50 KB by default — the reason the `moreproblem` rebuild re-renders the table into a `<pre>` before extraction.
